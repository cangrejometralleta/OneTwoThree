# Distillation Reaches a Codebase (UNDISTILLED)

The Canon's Passage — chaos, stories, then Values, Rules, Patterns —
was copied into an API that Follows it, with new destinations:

| Canon | Codebase |
| --- | --- |
| `chaos/` — private, never committed | `chaos/` — pilot logs, store emails, transcripts |
| `stories/`, cap 9, person removed | `stories/`, cap 9, work in progress |
| a Belief → Values | a Decision → `docs/`, both languages |
| a Rule → Rules | a Rule → code, held by a test |
| a Root → Patterns | a Promise → the API contract |
| README is the door | a root `MEMORY.md` is the door |

- The first story was an unfinished feature, not a lesson:
  a purchase flow half built, with its gaps named. In a codebase a story
  is also *work that has not stopped moving*, which the Canon never needed.
- Distilling means landing a piece where it governs, then deleting it.
  A test is the codebase's way of making a Rule executable.
- The Canon's own `.canonignore` already separates carried from taught;
  here `.gitignore` carries the chaos boundary alone.

Open: is this one Pattern with two instances, or a Rule the Canon should
teach every project? Does a code story need a status beyond UNDISTILLED —
say BLOCKED, when it waits on something outside the repository?

Distill when a second codebase keeps a Passage of its own.
