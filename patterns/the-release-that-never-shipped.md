# The Release Names a Snapshot

- `main` remains the Canon; a stable release names a useful snapshot for distribution.
- Keep release ceremony small: name the snapshot, describe what it offers,
  and let the Push announce it.
- A later `main` continues the work; a project that pins a release follows a Fork.
- Revert a bad change on `main`; publish a new release when a corrected snapshot is useful.
- Cooperative work later gave `develop` a deliberate role:
  shared Integration, with one Feature branch per Feature.
  [Branches Give Cooperation a Path](branches-give-cooperation-a-path.md)
  Describes that practice.
- The first stable release is `v1.0.0`; the historical `1.0.0` UNTAG remains intact.
- Historical details are in
  [Release Ritual History](../references/release-ritual-history.md).
